# Нативный UI строки списка серверов

## Итог
- Переработана строка списка серверов: убраны видимые шильдики Transmission/RPC и HTTP/HTTPS.
- Детали подключения перенесены в нативную info-кнопку перед именем сервера с hover-help и popover fallback.
- Кастомная macOS pill-кнопка добавления сервера заменена общей нативной toolbar-кнопкой.
- Статус подключения перенесён в начало строки и оставлен только в виде иконки; справа остались только storage summary и нативные действия.
- Кастомные capsule-плашки для статуса/storage и bordered/tinted edit/delete buttons заменены нативными SwiftUI labels/buttons.
- **[Update]** Настроены явные тинты кнопок строки (`.tint(.secondary)` для информации и редактирования, `.tint(.red)` для удаления), что предотвращает их автоматическое окрашивание в синий цвет при активности окна на macOS.

## Что сработало
- Небольшой тест дескриптора зафиксировал текст hover-help без хрупкой SwiftUI-интроспекции.
- macOS-сборка закрыла платформенный риск после iOS-ориентированной проверки.
- Использование явного переопределения `.tint(...)` поверх `.buttonStyle(.bordered)` решило проблему неконтролируемого окрашивания кнопок в цвет акцента macOS при фокусе.

## Ошибки / Риски
- Первичный широкий запуск `swiftlint lint --fix` попытался пройти по сгенерированным/build-артефактам; посторонних git-изменений не осталось, последующие lint-запуски были ограничены изменёнными Swift-файлами.
- Первый проход не довёл требование по статусу до конца: `Connected` остался справа текстовой capsule-плашкой. Для UI-правок с приложенным скриншотом нужно сверять каждый пункт запроса с итоговой композицией, а не только с кодовым diff.
- При использовании `.buttonStyle(.bordered)` на macOS кнопки автоматически окрашивались в системный цвет акцента (синий) при активном окне, если им не был явно задан индивидуальный `.tint`. Это лишало кнопки индивидуального цветового кодирования (например, опасного действия удаления).

## Извлечённые уроки
- Нельзя вкладывать маленькие action-кнопки внутрь row-wide кнопки; tap-target строки и detail/info controls должны быть отдельными.
- Для адаптивной стилизации строки семантические color tokens лучше держать рядом со строкой, пока их не заберёт общий app theme.
- Если пользователь просит нативные элементы, нужно удалять самодельные capsule backgrounds/padding там, где элемент может быть обычным `Label` или `Button`.
- Для server-list row статус подключения должен быть leading icon-only индикатором, а не trailing текстовым chip.
- **Влияние активного окна macOS**: Стандартные `.buttonStyle(.bordered)` кнопки сильно подвержены системной политике окрашивания окон. Чтобы избежать превращения всех кнопок в синие при активном окне, на них обязательно должен быть явно вызван `.tint(...)` с нужным цветом (например, `.secondary` или `.red`).
