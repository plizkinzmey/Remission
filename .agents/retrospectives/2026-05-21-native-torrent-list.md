# Нативный список торрентов

## Итог
- Заменил кастомную оболочку главного экрана торрентов на нативный SwiftUI `List`.
- Удалил закрепленный заголовок с blur-эффектом, кастомные карточные фоны строк, постоянную панель действий и неиспользуемые файлы заголовков/фонов.
- Перенес пустые состояния, ошибки и состояния без сети из секций `List` в overlay над списком, чтобы не провоцировать цикл AttributeGraph при `visibleItemsCache.updated` и пустом результате фильтра.
- Сохранил TCA-состояние, отправку команд, поиск, фильтр, категории, обновление, состояния без сети/ошибки, previews и accessibility identifiers.

## Что сработало
- Опора на существующие `TorrentListViewCoverageTests` позволила безопасно удалить компоненты, которые обслуживали только старый интерфейс.
- `.searchable`, `Picker`, `Menu`, контекстные меню и действия свайпом закрыли основной пользовательский сценарий без кастомных поверхностей.
- Запуск Periphery после удаления файлов выявил проблему формата `shellScript` в файле проекта, которая блокировала проверку мертвого кода.

## Ошибки / риски
- Запуск UI fixture для скриншота остановился на стартовом экране iOS, потому что UI-test dependency использует `TestClock`, который не продвигает таймер старта. Это выглядит независимым от рефакторинга списка, но ограничивает проверку fixture-пути через скриншот симулятора.
- Нормализация `PBXShellScriptBuildPhase.shellScript` в файле проекта была нужна для Periphery, но находится рядом с основным UI scope.
- Первая версия оставила `ContentUnavailableView` внутри секции `List`; на пустом результате фильтра это совпало с повторяющимся `AttributeGraph: cycle detected`.

## Что стоит повторять
- Для этого приложения нативные рефакторинги списков лучше строить вокруг одного общего `List` body с небольшими платформенными отличиями, а не вокруг отдельных scroll-контейнеров для macOS/iOS.
- Пустые состояния для нативного `List` лучше держать как overlay рядом со списком, а не как измеряемую строку или секцию списка.
- Если `swift-format` и SwiftLint спорят о размещении closure-параметров, именованная `content`-функция помогает не подстраиваться вручную под каждый инструмент.

## Дальнейшие действия
- Выполнено: UI fixture/scenario теперь пропускают стартовый экран на iOS через начальное состояние `AppBootstrap`, поэтому fixture-скриншоты детерминированно доходят до нужного экрана без ручного продвижения `TestClock`.
