# Исправление падения AnyNavigationPath при добавлении сервера на iOS

## Результат
- Успешно устранено критическое падение `comparisonTypeMismatch` при попытке добавить сервер на iOS.
- На iOS удален внутренний `NavigationStack` из `ServerFormView`.
- В `ServerListView.swift` при отображении формы редактирования сервера в виде модального `.sheet` на iOS добавлен `NavigationStack` вокруг `ServerFormView`. Это сохранило работоспособность заголовков и кнопок панели инструментов во всех сценариях отображения формы (как при пуше в стек, так и при модальном показе).

## Что сработало хорошо
- Глубокий анализ механизма навигации SwiftUI и поведения вложенных контейнеров `NavigationStack`.
- Четкое разделение ответственности: `ServerFormView` теперь является переиспользуемым компонентом представления (без собственного корневого контейнера навигации на iOS), а вызывающая сторона берет на себя ответственность за предоставление `NavigationStack` в модальном контексте.
- Запуск safety-gates (сборка `BuildProject`, полный прогон 479 тестов с помощью `RunAllTests`, валидация локализаций и мертвого кода) гарантировал отсутствие регрессий.

## Ошибки / Риски
- Ошибок в ходе реализации не возникло. Основной риск состоял в потенциальном исчезновении кнопок «Отмена»/«Сохранить» при отображении формы редактирования через `.sheet`. Этот риск был полностью устранен добавлением `NavigationStack` в вызове `.sheet` в `ServerListView.swift`.

## Выученные паттерны
- **SwiftUI Navigation Stack Hygiene**: Избегайте размещения жестко закодированных `NavigationStack` внутри вложенных или переиспользуемых представлений, которые могут быть запушены во внешний `NavigationStack`. Контейнер навигации должен настраиваться на уровне презентации (модального окна или координатора/роутера).
